# Web 前端开发守则

M3.5 重设计之后的长期约定，目的是防止后续开发让设计变差。设计的来龙去脉与评审记录见 [`ui-redesign.md`](ui-redesign.md)；本文只写「以后改界面时必须守住什么、怎么验证」。

## 1. 视觉基线

- **D 稿是锁定基线**：`.dev/design/explore/d.html`（本地文件，不入库）与截图 `shots/d-light.png`。工具调用卡、输入坞、左右栏的结构和细节以它为准。
- 独立评审的意见与 D 稿冲突时，**先问主人，不要直接改**。第 1 轮曾按评审意见把工具卡降成灰度行、去掉右栏描边和着色曲线，结果整体变粗糙，后来又恢复了。
- 北极星：对话是摊在桌面上的一份工作记录。结论留在纸面上，过程退到页边，需要你处理的东西才有颜色。新界面先拿这句话检查一遍。

## 2. 不可回退的设计要点

### 颜色

- 组件里**不写颜色字面量**。颜色只来自 `web/src/index.css` 的令牌。只有两个例外：外观设置的 6 个色块和 favicon。
- 主按钮用墨色（`variant="primary"`）。**强调色只给「需要你」的东西**：未读点、`awaiting_input`、发送、提交回答、批准计划、焦点环、链接、选中滑块。不要用强调色做装饰或分类。
- 绿、黄、红只表示成功、警告、错误。强调色的色相（默认 205）避开了这三条色带，新增预设也要避开。
- 强调色或成功色用在文字上时，改用 `--accent-ink` / `--good-ink`（混入了正文色，对比度 ≥ 4.5:1）。
- 小字最淡用到 `--text-faint`，它的对比度已满足 4.5:1。`--text-ghost` 只能用在装饰和禁用态，不能用在要读的文字上。
- 新增颜色时，明暗两套主题、6 个主题色预设都要截图看一遍。

### 材质分层

| 层 | 用在 | 类名 |
|---|---|---|
| L0 桌面 | 根背景、壁纸 | `.shell-wash` |
| L1 纸面 | 对话区、右面板、首页、设置主容器 | `.sheet` |
| L2 玻璃 | 页头、输入坞、菜单、弹层、命令菜单、toast、移动端抽屉 | `.glass` / `.glass-dock` |
| 内嵌井 | 代码块、输入框、终端、量表轨道 | `bg-inset` |

- 玻璃的模糊**写在 `::before` 上**，不写在宿主元素上。否则宿主会变成 backdrop root 和 fixed 后代的包含块，嵌套在里面的菜单就模糊不出来。
- **对话纸面保持 `overflow-visible`，裁剪只放在转录层**。Chromium 下，如果祖先同时有「圆角 + overflow 裁剪」，后代 `backdrop-filter` 上的 `mask-image` 会失效，页头玻璃就会多出一截空带、底边被硬切。
- 输入坞只用一个滤镜令牌 `--dock-filter`，不要另写一套参数。
- **输入坞完全独立悬浮**：托盘外面不加渐隐、主题色晕或净空带，周围的内容不受影响。「回到底部」按钮是悬在托盘上方 8px 的小圆钮，往上翻时盖在内容上，这是主人选定的取舍。
- 对话框面板用不透明的 `--panel`。`prefers-reduced-transparency` 下，以及浏览器不支持 `backdrop-filter` 时，玻璃会回退为不透明，新的玻璃组件也要走这条回退。

### 形状与尺寸

- 圆角只用令牌：`rounded`(4) / `xs`(6) / `sm`(9) / `md`(12) / `lg`(18) / `xl`(32) / `2xl`(36)。各档用途见 `ui-redesign.md` 的「令牌用途」。
- 全局使用超椭圆（`corner-shape: superellipse(1.6)`）。正圆和胶囊（`rounded-full`）保持 `round`。
- 圆角要同心：内层半径 ≈ 外层半径 − 间距。
- 最小字号是 `text-2xs`（11px）。**不写 `text-[10px]` / `text-[11px]`**。界面正文用 `text-xs`/`text-sm`，转录正文在 `.md` 里单独设为 14.5px/1.7。
- 非 Tailwind 的 CSS/JS 只引用原始变量 `--r-*`、`--sans`、`--mono`、`--sh-*`、`--ease`。

### 信息与文案

- **转录按 omp 的信息量全量展示**，不折叠成 `› N tool calls`。工具卡要保持「图标方块 + 圆角卡行」的形态。
- 工具卡展开后显示**完整参数**，不重复头部已经写过的内容。窄屏可以省略，但展开后必须能看到全文（路径、命令、PR 编号）。
- 模型名一律通过 `lib/model-brand.ts` 的 `shortModelName` / `modelBrand` 显示为短名，全名放进 `title`。同一个模型全站只有一种写法：头像 → 品牌 logo → 淡色短名。
- 成本只显示 `$0.24`，不再加美元图标。
- 上下文分类与 omp 的实际行为对齐（`lib/context-segments.ts`）。钉定的内核版本见 `core/source.json`（当前 omp 18.19.0）。改分类前先看对应版本的源码。
- 失败提示要说清楚「哪一步、为什么、下一步怎么做」。setup/resume 失败统一走 `lib/setup-diagnosis.ts`：原因加建议各一句，orbd 原文留在日志对话框里备查。不要直接把原始错误串扔给用户。
- 所有新增文案都要**同时**写进 `zh-CN.json` 和 `en.json`。

### 图标与字体

- 图标用 Phosphor，**逐个深导入**并登记进 `components/ui/icons.tsx` 的映射，不要整包导入。表示选中或实心语义时用 `weight="fill"`。不用 emoji 当图标（omp 标题卡里自带的 emoji 属于内容，可以保留）。
- 一个图标只表达一种意思，不要借用（例如拿时钟当刷新）。
- 字体：Mona Sans、思源黑体按需分片、JetBrains Mono，Nerd 私有区码点用字体只在需要时下载。不要新增字体。

### 动效

- 只做三类动效：主操作反馈、状态切换的来路、首页首次出场。
- 转录消息、列表行、悬停**不加入场动画**。退出不做动画。
- `prefers-reduced-motion` 时，所有动画和过渡一律压到 1ms。新动画必须走 `--ease` 和这条规则。

### 响应式

- 断点（`lib/viewport.ts`）：`compact` < 600 ≤ `medium` < 840 ≤ `expanded`。分支用 `useBreakpoint()` 判断，不自己读 `innerWidth`。
- 手机首页的工具行：附件和发送在上，分隔线下面是选项行。orb 是小圆圈；项目名先占够宽度，剩余空间够才显示模型名，否则模型也缩成圆圈；思考级别显示为模型图标右下角的角标。不要改回会折行的胶囊。
- 触屏没有悬停：悬停时才出现的操作（例如消息菜单）在触屏上必须能点出来（`tabIndex` + `group-focus-within`）。
- 改了窄屏布局，至少用 390 和 360 两个宽度验证。

## 3. 开发与验证流程

### 每次改界面

1. `bun run check`（biome + tsc）和 `bun run test`（vitest）。
2. 截图并亲自看图：
   ```bash
   cd web
   ORYN_SHOTS_DIR=/tmp/oryn-shots/<任务名> bun run shots:all --only <界面前缀> [--scheme light|dark]
   ```
   截图走 mock 后端，覆盖明暗两套主题、1280 和 390 两个宽度。改了共享样式（`index.css`、`primitives.tsx`、`tool-render.css`）时，去掉 `--only` 跑全量，并加上 `--check`（断言输入坞不遮挡最后一条转录，也包括软键盘弹出时）。
3. 关键区域在 100% 和 200%（DPR 2）下都要看。100% 下读不清的字不算通过。
4. 修 bug 要先写一个会失败的测试（红），再修到通过（绿）。截图类问题用一次性 playwright 脚本量尺寸或判断折行，用完删掉。

### 截图环境的坑

- 截图脚本用 SwiftShader（`--use-gl=angle --use-angle=swiftshader`）。默认的软件合成器在模拟 DPR 时 `backdrop-filter` 只部分生效，会误判成「玻璃不模糊」。别的脚本也要用同样的参数。
- 截图开了 `reducedMotion: "reduce"`，所以动效要另外在真实浏览器里看。

### mock 夹具

- mock 数据要和真实后端的**格式一致**。例如 setup 失败的 `error` 是 orbd 的 `<label>: exit status N`，原因写在日志尾部。用编出来的友好文案会掩盖真实的显示问题。
- 新增工具渲染器时，要往 `TOOL_ZOO_THREAD` 里加一个样例，`tools-*` 截图才能覆盖到它。

### 评审

- 大改之后找隔离上下文的评审员，按 oil-ui 评审手册做视觉 + UX + 代码三路评审。合格线是「可发布」：真实文字在 100% 下读得清，主角和主动作三秒内看得出来。
- 评审结论和处理方式记进 `ui-redesign.md` 的「评审记录」，不采纳的项也要写明理由。
- 和 D 稿冲突的意见，按第 1 节先问主人。

### 真机验收

- 改了线程页、终端、附件，跑 `bun run accept:m3`（T1–T14，真实 orynd + orb）。CI 有一个已知的偶发失败（`TestCatchUpBatchCursorAndTranscriptRev`），它和前端无关，重跑一次即可。

## 4. 新功能落位

Portal、Desktop、Ship/Review/Sync、Space、Artifacts 已经在 `ui-redesign.md` 的「未来功能落位」里定好了位置和形态，按那里接入，不要另起骨架，也不要提前放占位 UI。

## 5. 放弃过的做法（不要再提）

折叠过程只看结论、diff 行号列、自定义色相滑块、主题云同步（agent 头像除外）、按钮彩色投影、上亮下暗内高光、3D 球体头像、用户气泡着色、输入坞外的渐隐和净空带。原因见 `ui-redesign.md`。
