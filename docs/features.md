## 执行环境

Oryn 以 [Oryn Core](https://github.com/Lynricsy/oryn-core)（fork 自 [`can1357/oh-my-pi`](https://github.com/can1357/oh-my-pi)，MIT）为 Agent 内核，每个线程运行在自己的执行环境（orb）里。

### 四种执行后端

同一控制面可以同时接入以下后端，按项目或线程选用：

| 后端 | 隔离方式 | 说明 |
|---|---|---|
| Docker 容器 | 普通容器 | 默认剥离 `NET_RAW` 与 `NET_ADMIN` |
| Sysbox 嵌套容器 | 非特权 UID 映射 | 可在容器内运行内层 `dockerd`，无需 `--privileged` |
| Firecracker microVM | 独立 Linux 内核 | `/30` 点对点 tap 网络与 jailer 槽位隔离 |
| 本机 Runner | 个人机器上的普通用户进程 | 以 `orbd run --runner` 直连指定目录 |

本机 Runner 的目录已有活动线程时会报错，可在界面上选择新建 worktree，或用 `--worktree <名>` 在仓库旁新建独立的 `git worktree`。

### 项目快照与预热池

项目首次完成 `.oryn/setup` 后自动生成干净的磁盘快照（Docker 提交镜像，Firecracker 用 `reflink` 复制稀疏盘），之后的新线程跳过构建，直接运行 `.oryn/resume`。高频项目可配置 1–3 台常驻预热池，新建线程直接认领。

### 冻结、唤醒与停机

Agent 与用户空闲达到阈值后，orb 自动冻结（暂停容器或 vCPU），打开线程或访问受管服务时自动唤醒。冻结超时后转为停机，磁盘状态完整保留。停机的 orb 唤醒要冷启动，所以打开线程时不会自动唤醒它，只有发消息或手动唤醒才会。

停机期间文件面板仍可浏览和预览 orb 里的文件，且不会唤醒它：docker provider 从已停止的容器里读取，firecracker provider 在用户态解析 VM 磁盘（不挂载）。需要编辑时一键唤醒。

### orb 跟随线程

orb 是线程的执行环境，不是要用户挑选或清理的资源：

- 新建线程总是得到一台新 orb（或认领预热池）。界面上不列出已有 orb、不显示 orb 编号（信息面板悬停可见，供排查）。
- 线程全部归档后，orb 在下一轮空闲评估（≤30 秒）就冻结。归档线程的 orb 只冻结 / 停机、不删除，取消归档后可继续。
- 最后一个引用它的线程（含已归档的）删除时，orb 一并删除。「无引用」判定与进入删除在同一事务；挂载线程的写入事务会复核 orb 没有在删除，二者串行。
- 例外是定时任务的 `keepLast`：自动归档的旧运行只回收它独占的 orb。别的线程（哪怕已归档，例如从它「共用 orb」分叉出的线程）还在用就保留，同样在一个事务里判定。
- 命令行 `oryn thread new --orb` 与 API `executor.kind = "orb"` 仍可挂到已有 orb，留给脚本与高级用法。

### 环境自配置

项目的开发环境由生命周期脚本声明：

| 脚本 | 何时执行 |
|---|---|
| `.oryn/setup`（兼容 `.agents/setup`） | 新 orb 首次创建时执行一次 |
| `.oryn/resume` | 每次冻结后唤醒时执行，最长等待 10 秒 |

不便入库的脚本也可以保存在控制面的项目设置里（「环境」分组）。脚本退出非零不会阻塞 orb 就绪：工作台顶部显示诊断条，可以查看日志，或交给当前线程的 Agent（内置 `oryn-setup` 技能）修复。

仓库里的 Git LFS 文件不在克隆或更新仓库时随检出下载，由 setup 随后统一用 `git lfs pull` 取下。取不下时（对象不存在、凭据被拒、orb 里没有 `git-lfs`）setup 记为失败，线程里出现「环境 setup 失败」，没取到的文件仍是指针文本：修好原因后在仓库根运行 `git lfs pull`。

### 开发镜像

`images/orb/` 基于滚动更新的 Arch Linux 构建：x64 用官方 [`archlinux:latest`](https://hub.docker.com/_/archlinux)，ARM64 用每日构建的 [`menci/archlinuxarm:latest`](https://github.com/Menci/docker-archlinuxarm)。默认非 root 用户、UTF-8、`UTC` 时区，`~/.local/bin`、`~/.cargo/bin`、`~/go/bin` 与 npm 全局目录已在 `PATH` 里。

| 类别 | 预装工具链 |
|---|---|
| 语言与构建 | C/C++ (GCC/Clang)、Make、CMake、Ninja、Autotools、Go、Rust (`rustfmt`/`clippy`/`rust-src`)、Python (`pip`/`uv`/`pipx`/`ruff`)、Node.js (`npm`/`pnpm`/Bun)、Ruby/Bundler、PHP/Composer、Lua |
| 语言服务器 | 按 Oryn Core 内置 LSP 配置预装：`clangd`、`rust-analyzer`、`gopls`、`typescript-language-server`、`pyright`、`ruff`、`ruby-lsp`、`phpactor`、`lua-language-server`、`bash-language-server`、YAML / JSON / HTML / CSS / Dockerfile 语言服务器、`marksman` |
| 代码与协作 | Git、Git LFS、`gh`、OpenSSH、`rsync`、`ripgrep`、`fd`、`jq`、`yq` v4、`patch`/`diff`、ShellCheck、`shfmt`、常见归档解压工具（含 `unrar`/`cabextract`） |
| 排障与数据 | `ip`/`ss`/`dig`/`nc`/`socat`/`whois`/`nmap`/`iperf3`、`lsof`/`strace`/`ltrace`/`gdb`、`htop`/`ncdu`、SQLite / PostgreSQL / MariaDB / Valkey(Redis) 客户端、DuckDB、Miller、HTTPie、`aria2`、`yt-dlp` |
| 文档与媒体 | Pandoc、LibreOffice（`soffice --headless`）、Poppler/`qpdf`/Ghostscript/MuPDF/`img2pdf`、Tesseract OCR（英文、简繁中文）、ImageMagick、librsvg、WebP/AVIF/JPEG XL/HEIF 编解码、`optipng`/`pngquant`/`jpegoptim`/`gifsicle`、ExifTool、Graphviz、`qrencode`/`zbar`、FFmpeg、SoX、MediaInfo |
| Python 库 | 系统 Python 可直接 `import`：numpy、pandas、scipy、matplotlib、Pillow、requests、BeautifulSoup、lxml、PyYAML、openpyxl、XlsxWriter、python-docx、pypdf、ReportLab |
| 图形桌面 | TigerVNC (`Xvnc`)、Openbox、session D-Bus 与 AT-SPI 无障碍总线、受管策略加固的 Chromium、VS Code（微软官方版）、终端（`xfce4-terminal`）、文件管理器（`pcmanfm`）、文本编辑器（`mousepad`）、LibreOffice、中英文与彩色 Emoji 字体；等宽字体默认为 [JetBrains Maple Mono](https://github.com/SpaceTimee/Fusion-JetBrainsMapleMono)（中英文 2:1 对齐、带 Nerd Font 字形、无连字） |

交互 shell 的提示符只显示工作目录（如 `~/workspace $`，超过 3 级时前面折叠成 `~/.../a/b/c`），上一条命令失败时 `$` 变红；窗口与终端标题同样只显示工作目录，不带 `user@<orb ID>`。提示符是纯 ASCII，不用 Nerd 字形，agent 读终端文本和看截图时都能直接认出；非交互 shell 不受影响。

系统软件包记录在 `/usr/local/share/oryn/packages.txt`。ShellCheck、Pandoc、rust-analyzer、marksman、phpactor、JetBrains Maple Mono 从上游 GitHub 发行版安装（ARM 仓库缺包，双架构统一来源），VS Code 按微软更新 API 的 `sha256` 校验安装官方 tarball，版本一并记录在 `/usr/local/share/oryn/upstream-versions.txt`。桌面任务栏的应用清单在 `/usr/local/share/oryn/desktop-apps.json`，图标取自镜像内各应用自带的文件并收集在 `/usr/local/share/oryn/desktop-icons/`；不含该清单的自定义镜像在任务栏里只有内置的 Chromium。在项目 `setup` 脚本里增装系统包用 `sudo pacman -Syu --needed --noconfirm <包名>`。镜像已启用 [BlackArch](https://blackarch.org/) 源（双架构）：只导入经钉定签名主密钥校验的 keyring 与镜像列表，不预装安全工具；该源排在官方源之后，同名包仍取官方版本，其中的工具同样用上面的命令安装。跨架构构建 ARM64 镜像见 [`development.md`](development.md#跨架构构建-arm64-镜像)。

## 工作台

### 转录与工具卡

- **工具卡**：头部显示这次调用的意图，收起、展开都一样；没有意图时才显示参数摘要。展开体上半是输入，下半是输出井，用底色区分，不再写「输入 / 输出」标题。
- **用户消息的轻量 Markdown**：用户气泡里的每个字符都和原文一样显示（空白、换行、`#`、`**`、反引号、`>`、列表符号、围栏行都在），只给样式：语法记号变淡，标题与粗体加粗、斜体、删除线，行内代码与围栏代码块用等宽字体，引用变弱色，链接与裸地址可点（只认 http(s) / mailto）。便于核对输入，选中复制得到的就是原文。开头的引用回复块仍按原文显示。
- **待回复的回合头**：回合开始后、agent 还没有任何输出时，转录末尾立即出现 agent 的回合头（头像、名字、模型胶囊，模型取会话当前模型），下面是三个依次跃动的点；助手消息开始流式后由该回合自己的回合头在同一位置接替，三点留在这条消息里，直到首个可见的正文、思考或工具块到达（provider 首事件前的空消息、只有空 text / thinking 块时都还是三点）。回合中途（工具调用之间）仍是「工作中」与当前活动。
- **当前一批默认展开**：线程工作中时，最后一条助手消息里的工具调用（并行调用算一批）默认展开；模型开始下一批或回合结束时自动收起。手动开合过的卡片以用户为准。
- **语法高亮**：约 60 种语言；diff 按文件语言高亮代码部分，grep / ast_grep 结果按文件逐段高亮，命令行统一按 bash 高亮。
- **表格**：助手正文里的 Markdown 表格按内容需要放宽，两侧空间够时对称伸出正文列（最宽到转录行宽减两侧各 1rem、封顶 72rem），再放不下时横向滚动。各处的 Markdown 表格悬停（触屏点一下）时右上角都出现三个按钮：复制为 CSV、复制为 Markdown 表格（取原文，保留行内格式）、复制为图片（PNG）。
- **bash 的 Pseudo 视图**：bash 卡默认显示 Oryn Core 生成的 Pseudo 视图（令牌着色、失败标 ×、跳过的步骤弱化、变量终值），可切回原始命令。运行中随执行轨迹更新，正在执行的行首标 `›`，其余行弱化。Runner 线程只有最终结果带 Pseudo 视图。
- **后台任务**：转入后台的 bash / eval 调用（结果带 `details.async`）头部有一枚随任务走的标记：后台运行中（圆点扩散，状态位转圈）、后台已完成、失败、已停止，收起时也在；展开体末段是任务的最近输出与「查看任务」。任务注入会话的消息解析成事件行，不再是通用的 `async-result` 卡片：「后台任务 bg_3 已完成 / 失败 / 已停止」（命令、耗时，点开看结果并可复制，子 agent 的任务可直接打开它）、一次交付多个任务时汇成一行、`notify` 命中的「输出匹配 /正则/」、常驻进程退出。
- **思考档位**：转录回合头把模型放进胶囊，右下角用图标标出该回合的思考档位。首屏 role 弹层直接选中实际生效的档位，不再有「默认」项：显式指定的档位优先，其次是模型自带的默认档位，再次是会话起始档位（default role 的显式档位或 `config.yml` 的 `defaultThinkingLevel`），最后按模型能力收窄。推不出实际值时只列可选档位、不选中。
- **不显示的提示**：模型 / 思考级别切换不单独成行（回合头的胶囊与角标、输入坞已经显示）；omp 的 `xd://: mounted …` 挂载变动提示也不进转录（模型照样会随下一条消息得知变动）。

### 右键菜单与选区动作

右键弹上下文菜单；输入框里与 `Shift`+右键保留系统菜单。键盘菜单键（或 `Shift`+`F10`）在终端与普通输入框之外都能弹出；触屏长按只在转录消息、代码块、工具卡、侧栏线程行、收件箱行、文件树、改动列表与 Artifacts 卡片上弹出。

| 位置 | 菜单项 |
|---|---|
| 转录消息 | 复制消息、引用整条（助手消息），与行内「⋯」相同 |
| 链接 / 图片 / 代码 | 打开或复制链接；复制、下载图片或作为附件引用；复制代码、解释这段代码 |
| 工具卡 | 复制命令、路径或输出，在文件面板打开，解释这次调用 |
| 侧栏线程行、收件箱行 | 打开、状态、改名 / 标签 / fork、归档与删除 |
| 终端 | 有选区时的选区动作，粘贴、全选、清屏；只响应右键，程序开了鼠标上报时不出菜单。菜单键与触屏长按都留给 xterm 和终端里的程序 |
| 编辑器、文件查看器 | 选区动作（带文件路径与行号）、剪切 / 粘贴、复制路径与行号 |
| 改动列表与 diff | 在文件面板打开、复制路径、暂存 / 取消暂存；diff 里的选区可解释 |

**选区动作**：选中一段文字后，AI 组有「解释」「就此提问…」「翻译」和自定义动作（前三个直接列出，其余进「更多动作」），另有引用回复、引用到输入框、复制与在命令面板里搜索。AI 动作走旁路提问：选区原文、前后各 120 字与来源（回复、思考、工具卡、文件路径与行号）拼成问题，结果显示在选区旁的解释卡里，可追问、复制或转到旁路提问对话框；窄屏用对话框。自定义动作在「设置 → 选区快捷动作」里管理，至多 12 条，名称不超过 24 字、提示词不超过 2000 字。

### 收件箱与命令面板

- **侧栏「需要你」**：汇总等待输入或出错的线程，子线程状态上卷到父行。
- **`/inbox` 分诊台**：顶部是大号待处理数与状态筛选胶囊，分节按紧急程度排列：等你处理 → 出错 → 已完成未读 → 运行中。每行写明在等你什么：未作答的问题原文、完成摘要、出错原因或当前意图。
- **一触作答**：可一触作答的提问在行下方直接列出选项按钮，点选即作答；已在别处作答时提示并撤回。
- **出错说人话**：出错原因先归类成一句人话（镜像拉取被拒、找不到镜像、容器命令非零退出、连接超时等）并带上镜像名、退出码等小签，原文降为一行等宽小字。
- **命令面板 `Ctrl/⌘ K`**：跳转线程、项目、Space、Artifacts、设置与常用操作，并对全部对话正文做全文搜索（SQLite FTS5 trigram 索引，中文无需分词；fork 拷贝的同一条消息只计一次，命中后直接定位到该条消息）。

### 项目

「项目」分区回答「这个代码库现在怎么样了」。侧栏首行是「总览」（行尾 `+` 新建项目），其后每个未归档项目一行：名称加「N 个线程 · 多久前活跃」，按名称排序；停在项目的任一子页时该行都保持选中。要看某个项目的线程，进它的线程子页；线程分区侧栏不再有项目过滤签。

- **总览 `/projects`**：一行一个项目，依次是徽标、名称、描述与仓库地址、近 14 天每天回合数的活动曲线、线程数和最后活跃时间，按最近活动排序。线程数只算未归档、非协调对话的线程；最后活跃取其中最新一条的活动时间，没有线程时取项目创建时间。用量被折叠进「其它」的项目不画曲线，全零时画一条平线。页头 `⋯` 菜单里的「显示已归档项目」会在下面另起一张「已归档」卡，开关状态写进地址（`?archived=1`），刷新和切换分区后保持。主按钮「新建项目」进入 `/projects/new`。
- **项目主页 `/projects/<id>`**：页头是面包屑（项目 / 项目名）和几个按钮：复制项目链接、复制克隆命令（外部仓库是 `git clone <地址>`，Oryn 托管的仓库是 `oryn clone <项目名>`；没有仓库时没有这个按钮）、项目设置、新建线程（已归档的项目没有这个按钮；点它回到首屏，项目已选好）。正文自上而下：
  - 描述与仓库行：一行描述（最多 200 字，在设置的「概览」里填），仓库地址前的图标区分 GitHub 与其它 Git，Oryn 托管的仓库显示「Oryn 托管」，后面是基线分支；没有仓库时显示「无仓库」。
  - 状态条：等你回复的线程数、工作中（含准备环境中）的线程数、打开的 PR 数（其中 CI 失败的数量用红字追加在同一项里）、最近一次环境 setup 失败、近 7 天的成本与回合数。前三项链到线程子页的「活跃」筛选；setup 失败链到出事的线程，没有线程时链到设置的「环境」分组；成本一项链到统计页（`/stats/usage?range=7d&project=<id>`）。数值为 0 的项不显示，全部为 0 时整条不占位。
  - 最近线程：最近活动的 5 个线程（含已归档的），「查看全部」进线程子页。
  - 服务：本项目 orb 上的受管服务，失败和已停止的也列出；没有服务时不显示。
- **线程子页 `/projects/<id>/threads`**：搜索框匹配线程标题与标签（多个词都要命中）；状态分「全部 / 活跃 / 已归档 / 已交付」四档，各档可以重叠（已交付的线程同时算在「活跃」或「已归档」里）。搜索词与状态都写进地址（`?q=`、`?status=`），切走再回来筛选保持。每行显示状态、PR 与 CI、交付与归档徽标、最后活动时间。
- **设置 `/projects/<id>/settings/<分组>`**：宽屏左边是分组导航、右边是内容，窄屏先是一页分组列表、点进去看内容，面包屑里的「设置」返回列表。七个分组：
  - 概览：名称、图标、描述、仓库地址与基线分支、git 作者；「仓库镜像」卡（外部仓库）或「托管仓库」卡（Oryn 托管或还没有仓库，见[托管仓库](#托管仓库)）；「危险操作」里的归档 / 取消归档与删除项目。
  - 环境：默认模型供应商、orb 类型、浏览器 Profile、浅克隆、setup 与 resume 脚本；最近一次环境 setup 的结果；「快照与预热」（项目快照开关与预热 orb 数）。
  - Agent：项目级 Agent 配置（见[项目级中央配置](#项目级中央配置)）与项目记忆开关。
  - GitHub：仓库绑定、事件回流、触发规则与推送门禁；仓库不在 GitHub 上时只给出改仓库地址的入口。
  - 定时任务：本项目的定时任务。
  - SSH 主机：限定到本项目的 SSH 主机。
  - 密钥与环境变量：只注入本项目 orb 的环境变量与 Git 令牌（见[项目级密钥与环境变量](#项目级密钥与环境变量)）。
- **归档**：在「概览 → 危险操作」里归档，要确认。归档后项目从侧栏收起，GitHub 仓库钩子被释放，预热 orb 清零，定时任务与触发规则停止运行；线程都保留，仍可在总览的已归档区或直接打开项目地址查看，页面顶部有提示条和「取消归档」。取消归档不需要确认，项目回到侧栏，定时任务与触发规则重新生效。删除项目时线程保留但不再属于任何项目，定时任务、Agent 配置、项目记忆与项目级密钥和环境变量一并删除。

#### 仓库浏览

项目主页的提交、文件与 README 来自控制面自己维护的裸镜像 `<data_dir>/repos/<项目 id>.git`：外部仓库的完整镜像（全部分支与标签，不含 PR 引用），由 orynd 自己执行 `git`，不经过任何 orb。只支持 `https://` 仓库地址。

- **何时同步**：首次打开项目页（或任一仓库接口）时在后台克隆，页面先显示「克隆中…」；之后每次读取时距上次拉取超过 60 秒就在后台拉取，读取先返回旧数据；GitHub 项目另订阅仓库的 `push` 事件，推送后立即拉取；仓库行与设置「概览」的「仓库镜像」卡上有「立即同步」。首次克隆失败后不自动重试，等手动同步或推送事件。已归档的项目不自动克隆、不自动拉取，只能手动同步。改了仓库地址（指向另一个仓库）时旧镜像被删掉、按新地址重新克隆；GitHub 仓库改名（绑定的仓库 id 不变）只更新地址。删除项目时镜像一起删除。
- **凭据**：github.com 用你的 GitHub 账号令牌（没连接时匿名；项目里设的 `git/github.com/token` 不用于镜像），其它主机先用项目设置「密钥与环境变量」里的 `git/<主机>/token`，没有再用全局密钥 `git/<主机>/token`。令牌只经环境变量交给 git，不写进命令行与磁盘配置。没有令牌的非 GitHub 主机经公网地址守卫直连：只连 443 端口、只连公网地址，解析到内网的主机会被拦截。
- **主页区块**：描述与仓库行末尾是同步状态（已同步多久前、克隆中、同步中、同步失败的原因）与刷新按钮；「最近线程」旁是「提交到 <基线>」（基线分支最近 5 个提交，带关联线程的直接链到线程）；下面是「文件」（进入提交 / 分支 / 标签子页的入口、最新提交、根目录列表与每项最后一次改动的提交）和 README（根目录里的 `README.md` 等，按 GitHub 的规则解析相对链接与相对图片，超过 512 KB 截断）。
- **子页**：`/projects/<id>/commits`（可切换分支或标签，`?ref=`；宽屏左列表右详情，详情列出改动文件，逐个展开看 diff）、`/projects/<id>/branches`、`/projects/<id>/tags`（默认分支排第一，每行可进该 ref 的文件）、`/projects/<id>/files/<路径>`（目录列表或文件预览，只读，地址可直接分享）。
- **提交关联线程**：不改提交信息，按三种来源依次查找：线程推送（出站代理记下线程经它的 `git push` 推了哪个 ref、从哪个提交到哪个提交，镜像拉到之后展开成这次推送带来的提交，每次至多 500 个）；线程里出现过（线程运行时采样到的提交）；经 PR 合并（GitHub 项目打开提交详情且前两种都没找到时，按「提交所属 PR → 最早关联这个 PR 的线程」反查一次，补上 squash 合并；没有线程的结果 24 小时内不再反查）。
- **仓库区块不可用时**：主页只显示一条说明，「最近线程」与服务照常。

  |说明|含义|
  |---|---|
  |还没有关联仓库|项目没有仓库地址，去设置「概览」填写|
  |控制面未安装 git / git 版本过旧|控制面主机没有 git 或低于 2.31，仓库浏览停用，其余功能不受影响|
  |仓库尚未克隆|已归档的项目不自动克隆，点「立即同步」|
  |只支持 https:// 仓库地址|`git@…` 或带端口、用户名的地址不能镜像|
  |需要凭据 / 凭据被拒绝|私有仓库没有可用令牌：连接 GitHub 账号或添加 `git/<主机>/token`；或令牌无权读这个仓库|
  |找不到仓库 / 连不上仓库主机 / 拉取超时|上游 404、网络不通，或首次克隆超过 15 分钟、增量拉取超过 5 分钟|
  |仓库主机解析到内网地址，已拦截|没有令牌的主机只能连公网地址|
  |仓库超过镜像大小上限|镜像超过 `repos.max_mirror_gb`（缺省 5 GiB）：拉取中途被终止，或拉取完成后镜像被删除|
  |控制面磁盘空间不足|数据盘可用空间低于 `repos.min_free_gb`（缺省 2 GiB），不克隆、不拉取|
  |克隆中…|首次克隆可能需要几分钟，完成后自动刷新|
  |仓库是空的|镜像就绪但还没有任何分支，推送第一个提交后显示|

  已有镜像时拉取失败不影响浏览：继续显示旧数据，同步状态旁有告警图标说明最近一次失败的原因。
- **Git LFS**：文件列表里 LFS 文件带「LFS」标记，大小是对象的真实大小；打开文件时控制面按需向仓库主机取对象，控制面主机不需要装 `git-lfs`。取对象用与镜像拉取相同的凭据，而且只用仓库主机自己的 LFS 接口，不读仓库里的 `.lfsconfig`，令牌只发给它所属的主机。取到的对象放进本地缓存（所有项目合计 `repos.max_lfs_cache_gb`，缺省 2 GiB，先清最久没用的）。超过 100 MiB 的对象不在浏览器里预览，只能下载；取不到时文件页显示原因（对象不存在、凭据被拒、连不上存放对象的主机、内容与指针不符、磁盘空间不足）和「重试」。提交的 diff 显示的是指针文本的改动。

#### 托管仓库

项目也可以不接外部仓库，由 Oryn 保存正本：仓库就是 `<data_dir>/repos/<项目 id>.git`，orynd 自己执行 `git upload-pack` / `git receive-pack` 提供 smart-HTTP，克隆地址是 `https://<Oryn 地址>/git/<项目 id>.git`。提交、文件、README 与各子页和外部仓库一样（读的就是正本本身），只是没有同步的概念：仓库行没有同步状态与「立即同步」。

- **仓库来源**：新建项目时在「仓库」里三选一：「已有仓库」（填外部 `https://` 地址，即上节的镜像）、「空白仓库（Oryn 托管）」、「不带仓库」。空白仓库建好就带一个空树的初始提交 `Initial commit`（没有 README），作者依次取项目的 git 作者、全局 git 身份，都没有时为 `Oryn <oryn@<Oryn 主机名>>`；基线分支缺省 `main`。没有仓库的旧项目可以在设置「概览」的「托管仓库」卡里点「创建托管仓库」（已归档的项目要先取消归档）；之后新建的 orb 会克隆它，正在运行的 orb 不受影响。托管与外部仓库不能互转：托管项目不能再填外部仓库地址，有外部仓库的项目也不能创建托管仓库。
- **在哪显示**：仓库行、总览与首屏的项目选项写「Oryn 托管」；设置「概览」的「托管仓库」卡显示克隆地址（可复制，下面写着对应的 `oryn clone` 命令）与推送后 Webhook。
- **本机用法**（先 `oryn login`）：
  - `oryn clone <项目名|id> [目录]`：克隆托管仓库，并在新仓库里把 `oryn git-credential` 登记为该主机的凭据助手（先清空这台主机的其它助手，设备令牌不会被系统钥匙串之类的助手存走）。之后的 fetch、push 与 `git lfs` 都用 `oryn login` 的设备令牌认证。克隆地址的主机与登录的服务器不同时直接报错，提示用 `oryn login --url` 重新登录；外部仓库的项目提示直接 `git clone <地址>`。目录缺省是项目名。
  - `oryn project create <名> --hosted`：新建托管项目（带初始提交），输出项目 id。
  - `oryn project create <名> --push [--remote <名>]`：在本机已有的仓库里运行，把它建成托管项目：基线是当前分支，服务端建一个没有提交的空仓库，本机加远端（缺省 `origin`；已有 `origin` 时报错并提示 `--remote`，如 `--remote oryn`）、登记凭据助手，然后 `git push -u`。仓库里有 Git LFS 文件时先 `git lfs push --all`（本机没装 git-lfs 时不建项目）。分离 HEAD、还没有提交的分支、不是 git 工作区都会在建项目之前报错；推送失败时项目保留，按提示重跑 `git push -u <远端> <分支>` 即可。
  - `/git/` 只认设备令牌（HTTP Basic 的密码位，用户名任意；或 `Bearer`），浏览器的登录会话不能用来访问它。
- **orb 里**：托管项目的 orb 从克隆地址克隆，`git remote -v` 显示的就是它；orb 的 git 与 LFS 请求经出站代理回到控制面在本地服务，不出网、不注入任何令牌。orb 只能访问本项目的托管仓库，只读评审线程不能推送；agent 推上来的对象先过 `git fsck`（带 `.git` 路径项或恶意 `.gitmodules` 的树进不来）。
- **交付**：托管项目的改动面板是「提交并推送到 <基线>」：给线程发一段固定提示词，让 agent 提交、rebase 到 `origin/<基线>`、`git push origin HEAD:<基线>`（被拒时重来，不强推）。线程把提交推上项目基线分支后自动标记「已交付」，推送带来的提交关联到这个线程（来源「由该线程推送」）。主人本机的推送不关联线程，只刷新页面并触发 Webhook。
- **推送后 Webhook**：只有托管项目有，只有主人能在设置里改，助手改不了。地址须是 `http://` 或 `https://`，不能带用户名密码；签名密钥可选，保存后不再显示，留空保存表示不改，「清除密钥」去掉签名。每次推送成功后异步 POST 一次 JSON：不阻塞推送、不重试、不跟随重定向（3xx 算失败），10 秒超时；同一项目同一时刻只投一个，积压超过 8 个时丢弃这次并记为失败。设置里显示最近一次投递的时间与 HTTP 状态码，或失败原因。线程里 agent 的推送同样触发（`pusher.kind` 为 `thread`），要不要据此部署由接收端把关。

  请求头：`Content-Type: application/json`、`User-Agent: Oryn-Webhook/<版本>`、`X-Oryn-Event: push`、`X-Oryn-Delivery: <deliveryId>`，设了密钥时还有 `X-Oryn-Signature-256: sha256=<hex(HMAC-SHA256(密钥, 原始请求体))>`。载荷：

  ```json
  {"event":"push","deliveryId":"whd_01J…","pushedAt":1795000000000,
   "project":{"id":"prj_…","name":"demo","cloneUrl":"https://oryn.example.com/git/prj_….git"},
   "pusher":{"kind":"thread","threadId":"T-…"},
   "refs":[{"ref":"refs/heads/main","oldSha":"<40 位十六进制>","newSha":"<40 位十六进制>"}]}
  ```

  `pusher` 是 `{"kind":"owner"}`（主人本机）或 `{"kind":"thread","threadId":…}`（orb 里的 agent；找不到唯一的工作线程时不带 `threadId`）。`refs` 是这次推送改动的全部 ref，新建分支的 `oldSha`、删除分支的 `newSha` 是 40 个 `0`。接收端按原始请求体校验签名，例如：

  ```python
  import hashlib, hmac

  def verify(secret: bytes, body: bytes, header: str) -> bool:
      expected = "sha256=" + hmac.new(secret, body, hashlib.sha256).hexdigest()
      return hmac.compare_digest(expected, header)
  ```
- **基线分支不设保护**：任何分支都可以强推或删除。被删除或被强推覆盖的分支旧值在仓库里留存 30 天，存为 `refs/oryn/saved/<毫秒时间戳>/heads/<分支>`；这些 ref 对 git 客户端不可见、也改不了。需要时在控制面主机上以 orynd 的用户取回，例如 `git --git-dir <data_dir>/repos/<项目 id>.git for-each-ref refs/oryn/saved/` 找到旧值，再 `git --git-dir … branch <新分支名> <那个 ref>`。
- **归档与删除**：归档后仓库只读：能克隆，不能推送，也不能上传 LFS 对象。删除项目连仓库一起删除（全部分支、标签、提交与 LFS 对象，确认框写明），不可恢复；托管仓库没有别的副本，备份见 [deploy.md](deploy.md#2-控制面配置-etcorynorynd-yaml)。
- **Git LFS**：托管仓库内置 LFS 服务（批量接口 + basic 传输），主人本机与 orb 都能用：`oryn clone` 之后 `git lfs` 自动带设备令牌，orb 里经出站代理。不支持文件锁：锁接口一律回 404，git-lfs 据此自动关掉推送前的锁校验。对象存在仓库目录的 `lfs/objects/` 下，计入仓库大小、随项目删除；网页上超过 100 MiB 的 LFS 文件同样只能下载。
- **容量**：不设仓库大小上限，也不额外安排清理；数据盘可用空间低于 `repos.min_free_gb`（缺省 2 GiB）时拒绝推送与 LFS 上传。

#### 项目级密钥与环境变量

项目设置的「密钥与环境变量」分组是一张表，存这个项目自己的环境变量与 Git 令牌。值只注入本项目的 orb（setup 脚本、agent、受管服务），别的项目看不到；全局「密钥」设置页不变。

- **能设什么**：环境变量（名称须是大写字母、数字和 `_`，不能以数字开头）与 Git 令牌 `git/<主机>/token`（在表单里选「Git 令牌」后填主机，主机名小写）。模型供应商密钥（`omp/models/…`）只能在全局设置。
- **保密与不保密**：环境变量可以勾「保密」（缺省勾选）：保存后值不能再查看，列表里只显示点，编辑时只能输入新值覆盖；把保密的条目改成不保密也必须重新输入值。不勾就是普通环境变量，值在列表里可见、可直接改。Git 令牌总是保密。保密的值和全局密钥一样参与分享前的密钥扫描与主人记忆脱敏（命中时显示为 `<项目名>:<变量名>`），不保密的值不参与。
- **同名时的优先级**：全局环境变量 < 项目条目 < 模型供应商密钥降级成的环境变量。Git 令牌按主机取：先项目、后全局；但 github.com 在 orb 归 GitHub 集成管时一律用 OAuth 账号令牌，项目里设的 `git/github.com/token` 只在 orb 不归 GitHub 集成管时生效，仓库镜像的拉取也不用它（见[仓库浏览](#仓库浏览)）。项目令牌读取出错时直接拒绝，不回落到全局令牌。
- **批量添加**：「批量添加」里粘贴 `.env` 内容，每行一个 `KEY=value`，支持 `#` 注释（含值后面以「空白 + `#`」开头的行内注释）、`export` 前缀、单引号与双引号（双引号里认 `\n`、`\"`、`\\`），不支持跨行的值。预览逐项列出变量名与值，每项可单独勾「保密」（缺省勾选），与现有条目同名的标出「覆盖现有」；缺 `=`、变量名不合规、值为空、引号没闭合、引号后有多余内容的行列在「以下行不会导入」里，重名的以后一行为准。导入逐项写入，失败的项留在对话框里并写明原因。
- **谁拿不到**：Runner 线程（个人机器）与协调宿主不下发项目条目；全局助手与 Space 协调者没有读写它们的工具。
- **何时生效**：环境变量在 orb 下次启动时生效，正在运行的 orb 不变；改环境变量会使本项目的快照失效（新 orb 重新跑 setup），预热池随之按新配置对账。Git 令牌不进 orb，由出站代理在每次 git 请求时现取，改值立即生效、不影响快照；为一个新主机加令牌后，orb 要下次启动才会把该主机的 git 请求交给出站代理。
- **归档与删除**：已归档的项目仍可查看与修改条目；删除项目时条目一并删除。
- **命令行**：`oryn secrets set <名称> [值] --project <项目>`（不给值时从标准输入读；`--plain` 存为不保密的环境变量；不给 `--mode` 时 `git/` 开头的名称按 Git 令牌、其余按环境变量）、`oryn secrets ls --project <项目>`（保密的值显示 `-`）、`oryn secrets rm <名称> --project <项目>`。`--project` 只认未归档项目，已归档项目的条目在网页上改。例：`oryn secrets set FOO bar --project myproj --plain`。

### 输入框

- **引用回复**：在 agent 回复里选中一段文字即可「引用回复」，引用以 Markdown 引用块随消息发出（运行中自动走 steer）。有选区时转录暂停自动贴底，流式输出不会把选区冲走。
- **`#` 引用**：键入 `#` 可以把 GitHub issue / PR 连同评论作为附件引用。
- **回退（Esc Esc）**：同 omp 的 Esc Esc。空闲时在空输入框里连按两次 Esc（或输入 `/branch`、`/rewind`）打开回退选择器，列出当前分支上你发过的消息，最近的在前，方向键挑选、Enter 回退；也可以在某条用户消息的菜单里点「回到这里编辑」。回退在原线程里把会话移回那条消息之前（原来的路径保留为分支，会话树里随时能切回），原文与附件放回输入框：附件直接复用原来的上传，图片连同内联副本一起放回；全局助手对话里的文件库文件不会放回。提示条上的「撤销」把会话与输入框都恢复到回退之前。回合进行中连按两次 Esc 仍是中断；输入框里有字时 Esc 不计入连按。从会话树跳到某条用户消息时，原文与附件同样会放回输入框。
- **下一条消息预测**：在 设置 › Agent › 输入框 打开后，每轮正常完成都会用当前模型猜你接下来要发的消息，以灰色文字显示在空输入框里（omp `composer.predictions`，Oryn Core 把它接进了 RPC 模式）。按 Tab 或 → 插入，不会发送；触屏上点一下灰色文字也能插入。打开「多个候选」后最多给出 4 条，插入一条后再按 Tab 换下一条。草稿只要还是某条预测的开头，提示就一直跟着显示；新回合开始、清空上下文或跳转会话树时，旧预测自动撤回。默认关闭：每完成一轮都会多发一次计费请求，请求带着整段对话。

### 远程桌面与人机控制

远程桌面有统一的控制状态（空闲 / Agent 操作中 / 用户已接管 / 等你操作），由 orbd 权威维护，所有设备一致。Agent 回合中面板默认只读观看；用户一键接管后，Agent 的浏览器 CDP 命令被挂起并经 steer 告知，交还或超时自动恢复。遇到登录、验证码、二次验证时，Agent 调用 `desktop_ask_user` 阻塞等待，桌面面板横幅、线程卡片、推送与 Telegram 都能点「完成 / 跳过」作答。

- **任务栏与窗口**：线程右面板的「桌面」标签与 `/assistant/computer` 的「桌面」页签共用同一视图。桌面背景为中性浅灰，窗口带标题栏（最小化、最大化、关闭），Chromium 与 VS Code 默认最大化。画面下方居中一条网页绘制的任务栏（不占远端画面），依次为 Chromium、终端（`xfce4-terminal`）、VS Code（微软官方版，经 VNC 使用）、文件管理器（`pcmanfm`）、文本编辑器（`mousepad`）、LibreOffice，图标取自 orb 镜像内各应用自带的图标；运行中的应用下方显示中性色圆点。点击未运行的应用启动；单窗口时点击在前台激活与最小化之间切换；多窗口（或右键、长按、`Shift`+`F10`）弹出窗口列表（切换、关闭）与「新建窗口」；不属于清单内应用的窗口归入末尾的「其它窗口」。Agent 操作中点击任务栏会先确认接管，接管后再执行操作。旧版 `orbd` 未上报应用列表时，退回画面中央的「启动浏览器」按钮。
- **无障碍树**：`orbd` 启动 session D-Bus 与 AT-SPI 总线，向桌面进程与 Agent 注入无障碍环境变量（VS Code 附带 `--force-renderer-accessibility`）。Agent 在 `eval` 的 `computer` 中可直接读取这些应用的无障碍树（`win.ax()`），不再只靠截图加坐标操作；Chromium 网页内容仍由 `browser` 工具经 CDP 读取。
- **桌面 `resume` 脚本**：按顺序查找线程工作目录（项目自定义 `workdir` 优先，有仓库时缺省 `$HOME/workspace/repo`，否则 `$HOME/workspace`）下的 `.oryn/desktop/resume` 与 `$HOME/.oryn/desktop/resume`，执行第一个存在且可执行的脚本（工作目录分别为该 `workdir` 或 `$HOME`）。每次显示栈启动且工作区就绪后执行一次：冻结后唤醒不重复执行，已开窗口原样保留；停机再启动或显示栈崩溃重启会重新执行；拍项目快照前带 `deferResume` 的 `setup.run` 不触发，留给随后的 `resume.run`。输出写入桌面日志 `~/.cache/oryn/logs/desktop/resume.log`，`orbd` 最多等待 60 秒、超时不杀进程。
- **录屏**：线程内 Agent 用 `desktop_record`（`{action: "start" | "stop"}`）录制桌面，按 15 fps H.264 写入 `$HOME/recordings/*.mp4`，单次最长 10 分钟，保留最近 20 个文件；停止后对话里出现可直接播放的视频卡片，点击播放时才请求文件，不会因打开对话唤醒冻结的 orb。全局助手用 `computer_record` 录制电脑桌面，停止后存入文件库（大小上限同 `computer_download`，超过则留在电脑上）。用户接管桌面、Agent 调用 `desktop_ask_user` 请求人工操作或回合结束时，`orbd` 先结束录制再放开人工输入；`user` 与 `ask` 状态下拒绝开始录制（`control_user`）。
- **已知限制**：多个线程或助手对话共用同一个桌面时没有租约，同时操作 GUI 会互相干扰；「助手的电脑」平时处于 `idle` 状态，在 `idle` 下开始的录制期间若用户同时在桌面面板里操作，输入会被录进视频。

## Agent 配置

### 图形化配置，保存即生效

设置页「Agent」分组把技能、子 Agent、模型角色、提示词与上下文、命令 / 规则 / 提示片段、扩展 / hook / 工具做成表单。编辑 `config.yml` 时保留原有注释，启停沿用 Oryn Core 的 `disabledExtensions` 与 `task.disabledAgents`；原始文件浏览器保留为「高级」入口。

保存后数秒内下发到所有运行中的 orb。技能、命令、规则、上下文文件与 MCP 在会话空闲时热重载；hook、扩展模块、自定义工具等需要重启的改动，页面顶部列出受影响的会话，可一键安排空闲时懒重启。

### 项目级中央配置

每个项目在控制面另有一层 Agent 配置，内容可以是规则、技能、子 Agent、命令、提示片段、扩展、hook、工具、`mcp.json`、`config.yml` 与 `AGENTS.md`。在项目设置的「Agent」分组里编辑，或用 `oryn config push|pull --project <项目>` 同步。

- 每次 setup / resume 时，这一层原样镜像到 orb 的 `~/.oryn/project-config/.omp/`，不写进仓库工作区，`git status` 保持干净。
- 同名条目的优先级是「项目层 > 仓库 `.omp/` > 全局」；`AGENTS.md` 与仓库里的并存。
- `/omfg` 生成规则后可以选「本项目」或「全局」，规则写回中央，由新建或唤醒的 orb 拿到。

约束：

- 全局与项目两层合计的下发编码不能超过 88 MiB，超过时写入返回 413。
- `models.yml` 只能放在全局层。
- 规则、`.md`、`.yml`、`.json` 都必须是 UTF-8 文本。
- 为防止不可信仓库借符号链接把本机文件（如 `~/.ssh`）传上去，`config push --project` 拒绝以下情况：推送目录本身是符号链接，或其中有指向目录外、无法解析、指向被排除路径的链接。全局推送仍照常跟随 `~/.omp/agent` 里指向别处的链接。两种推送都只收普通文件，`--exclude` 与 `.orynignore` 同时按链接名和真实路径匹配。
- 同一线程同时只能有一个 `/omfg`。
- `/omfg` 写回中央的规则必须与确认时的预览一致；中央已有同名但内容不同的规则时不覆盖，需要到 Agent 配置里手工合并。

### 中央模型目录

控制面用钉定版本的 Oryn Core 一次性运行 `omp models` 生成模型列表（`models.yml` 自定义 provider 与有密钥的内置 provider，附各自的思考档位与模型自带的默认档位）。设置页、首屏与线程内三处共用，无需打开线程或唤醒 orb；配置变化后自动重算，24 小时过期，也可手动刷新。

### 头像

默认 Agent 身份、全局助手、每个 role（含内置 role 与不在轮换里的 role）和每个子 Agent 都能设头像，内置 role / Agent 自带默认 Nerd 字形。子 Agent 总览、详情与 task 卡片用头像加光环动效区分运行、排队、完成、失败与仅存转录；公开分享页只带出分享范围内实际用到的 Agent 头像。

头像与项目图标共用一个选择弹层：点图标（头像为「内置图标」按钮）打开，分「图标」与「表情符号」两页。「图标」收录 Nerd Font 的开发品牌与语言、Linux 发行版和 Material Design 全集（约 7500 个），「表情符号」收录 Unicode 15.1 的全部 emoji（不含肤色变体）；每页顶部是「常用」精选。搜索为模糊匹配，可用多个词与按序缩写（如 `lang ts`），emoji 还可以用中文名和关键词搜。完整目录在第一次打开弹层时才加载。项目图标弹层右上角的「自动」清除手选的图标。

## 全局助手与 Space

控制面内置 `@host` 协调宿主，按需在独立系统账号、Landlock LSM、seccomp-bpf 与 Linux 命名空间围成的严格沙箱中拉起协调进程；沙箱里唯一能连的是回环上通往 orynd 的出站代理端口。

### Space 协调者

只开放内置 `read` / `write`，负责拆解阶段目标、并发创建与检视工作线程，并在需要人工决策时汇总提醒。它不能联网、没有 MCP，也不能读写或操控 Runner 线程。

### 全局助手

按三层执行，能自己做的就不派线程：

1. **自己动手**：omp 自带的 `web_search`、用 `read` 读网页、`generate_image` 生图，全局 `mcp.json` 里的 HTTP / SSE MCP 服务器，以及 artifact（含截图、导出进文件库、导入、从回收站恢复）。
2. **遥控「助手的电脑」**（见下）。
3. **派出与管理 agent**，操作面接近主人：在项目、Space 或 Runner 目录里开线程（可指定 provider、类型、已有 orb、role）；给工作线程或 Space 的协调对话发话并收回报；其余主人在 Oryn 里能做的事——线程、线程文件、项目、Space、box、orb、分享、artifact、定时、GitHub、SSH 主机、记忆、通知、密钥与各项设置——都经 `oryn` 工具完成。

**`oryn` 技能**：助手的顶层工具只留常用的一组，其余能力收进内置技能 `oryn`（`skill://oryn`）：`SKILL.md` 索引 18 个域，每个域一份操作清单，每个操作一份带参数 JSON Schema 的文档，全部由 OpenAPI 规格与策略表在运行时生成、经协调宿主的 omp-home 下发，只在用到时读取，不占常驻上下文。助手读完文档后调用 `oryn{op, args}`：REST 操作在进程内走与网页相同的处理器（主体是助手对话），少数带协调语义的操作（中止、改模型、线程文件、artifact 的版本 / 评论 / 页面数据 / 导出导入）转给原有实现。每个 REST 操作在策略表里逐个定级：读类直接执行；写类计入限速并记进「自动化 → 操作记录」（动作「接口操作」）；删除、对外公开、凭据与安全设置走确认卡；需要主人本人到场、结果是一次性凭据或二进制内容的不开放，并在文档里写明替代做法。新增接口必须先在策略表里分类，否则测试不通过。

**联网的边界**：沙箱本身仍连不到外网。助手的请求只经 orynd 的正向代理出去，代理在连接时按实际 IP 判定，只连公网地址；MCP 的鉴权头由 orynd 注入，不进沙箱。「设置 → 全局助手」有联网总开关，MCP 服务器可以逐个关掉。

**确认卡**：删除（线程、项目、Space、定时、触发规则、orb 等）、让未登录的人能访问的分享（线程分享链接、Portal 公开预览、以访问码或公开方式发布 artifact、公开 box 应用）以及密钥、凭据与安全相关设置不会直接执行。对话里先出现确认卡（卡片正文里的密钥值打码），同时推送带「是 / 否」的通知；主人点了「是」才由 orynd 执行，结果以自动消息回到对话，24 小时没人答就过期。新建、修改、归档、发消息不需要确认。登录与 Passkey、设备配对、provider / runner 令牌、绑定 Telegram 与作答确认卡只能主人本人做。

### 首屏直达

首屏输入框的 role 胶囊可选全局助手、轮换里的 role，或直接指定模型与思考档位；胶囊直接显示当前生效的选择，档位以右下角图标标出。输入框背后是一层向上渐隐的点阵，两侧各一条渐变的线止于输入框边缘，颜色随对象。选全局助手时执行位置与项目胶囊收起、点阵染上助手色并缓慢呼吸、线上有光流向输入框（普通对象静止），发送即新建助手对话并带上首条消息、附件与所选模型。「新对话默认对象」存在服务端，各设备一致。

### 主人记忆

全局助手有一份只关于主人的记忆（bank `oryn-owner`，与工程记忆同一个 Hindsight）。

- **写入**：助手对话与工作线程空闲 30 分钟、归档或交付后，主人的话连同助手的最后一条回复按回合写入。写入前用与分享相同的密钥扫描规则和密钥库值脱敏；工具调用、thinking 与长代码块不写。
- **整理**：每天整理出主人的长期主题（固定的「主人画像」加至多 12 个动态主题），在助手启动时附在系统提示词末尾。
- **工具**：`recall_memory`（判断模型重排，带出处与可信度分档）、`search_history`（原文全文搜索）、`recall_engineering`（只读工程记忆）、`remember`（主人原话直接生效，否则待确认）。
- **管理**：「更多 → Agent → 记忆 → 助手记忆」可查看注入预览、主题、事实与出处，让事实失效、按来源遗忘、排除对话或项目，审核明确记忆。

### 文件库

以下文件统一进入文件库：

- 助手对话里的附件；
- 助手写到 `~/library/out/` 的文件和生图结果（`~/tmp/`），用 `save_file` 存入；
- 从工作线程的 orb（`fetch_thread_file`）或助手的电脑（`computer_download`、`computer_record`）取回的文件；
- `export_artifact` 的导出物；
- orb 内 Agent 用 `oryn library put` 存入的文件。

文件库同步进协调宿主沙箱，供 omp 自带的 `read` 读取（PDF、Office、图片、压缩包、SQLite 等）。助手开新线程时可以附带库文件，也能用 `put_thread_file` / `computer_upload` 把库文件放进线程的 orb 或自己的电脑。全局助手页的文件库面板可以预览、下载、删除、切换共享并查看来源。

### 主线

助手分区最上面置顶一条永久对话，显示助手的名字和头像。它不能归档或删除，不进对话列表；打开助手分区时仍落在最近的普通对话。主线里的消息有四个来源：勾了「交给助手」的定时（`new_thread`）与 GitHub 触发规则的运行结果、主人在主线里让助手派出的线程的回报、助手在主线里给自己设的提醒、后台研究的发现。

- **交给助手**：每次运行的结果在 15 秒内合并成一条自动消息进主线，该运行不再单独推送完成通知（出错、等输入照常通知）。助手结合记忆判断值不值得说；不值得就调用 `stay_silent`，这一轮不置未读、不推送。
- **提醒**：主线可以有多条线程内定时（按名字管理，至多 50 条）。
- **后台研究**：主人没问的时候，助手自己去看新信息，值得说才在主线里说。「设置 → 全局助手 → 后台研究」有总开关（缺省关闭）、四条管线的开关、研究员用的模型、每日花费上限（缺省 20 美元）与一段研究偏好。
  - **跟进清单**：主线页头的「跟进」列出话题，可以新建、编辑、暂停、删除和立即检查。话题有两种：「问题跟进」带当时的回答作基线，30 天后结束；「长期关注」不结束。
  - **公网话题跟进**：话题登记 24 小时后第一次查；没有新东西时间隔翻倍，最长 7 天；有新发现时回到 24 小时。查的是一个只拿到话题标题与问题的研究员，它能搜索、读公网网页，读不到本地文件、别的对话和任何私有数据。主线助手拿发现对照当时的回答，回答过时或有误就主动更正。助手的联网开关关着时不查。
  - **自动挖掘**：助手对话与主线静止 30 分钟、且有新的主人消息时，从中挑出值得跟进的话题自动登记（每个对话每次至多 3 个，带网址或 `@` 的不登记，活跃话题至多 50 个）。登记后主人在清单里改或删，不逐条确认；删掉的话题不会再被同名登记。
  - **工作线程里登记**：主人在工作线程里让 agent「跟进这个」时，agent 用 `oryn follow add --title … --question … --quote "<主人原话>"` 登记；控制面核对原话确实出现在该线程的主人消息里，否则拒绝。有结果时只进主线，并注明来自哪个线程。
  - **内部关联**：工作线程有新消息时，至多每 2 小时让另一个不能上网的研究员翻看线程，报告跨线程的矛盾、重复与卡住（每次至多 3 条）；没有新消息就不调用模型。
  - **MCP 检查**：每 60 分钟用主人自己的 MCP 服务器（邮件、日历等）里勾选为「研究可用」的工具查看新内容，报告需要主人处理的事项（每次至多 5 条）。工具要在 MCP 卡片的「研究可用工具」里逐个勾选，缺省一个都不勾。
  - **受限的一段**：来自网页、邮件、日历的发现，只交给一轮工具受限的主线：只能读、能 `stay_silent`，不能开线程、发消息、用电脑、联网或改任何东西，也不能改备忘。这一轮结束后主线恢复全部能力，主人想让它动手时回一句即可。内部关联的发现照常交给完整的主线。
  - **折叠显示**：发现在主线里折叠成「幕后 · 后台研究」，展开能看到标题、摘要、来源链接与关联的线程。
  - **花费上限**：研究员当天的花费达到上限后，当天不再研究，并发一条预算通知。
- **分段运行**：为了让每次输入的上下文保持很短，主线一段一段地跑。每段开头清空上下文，只带一份备忘和最近 12 条消息（主人的话与助手说出口的话，沉默的回合不算）。备忘由助手用 `update_main_notes` 整体改写，1500 字以内，主人可以在页头查看和编辑。主线静止 10 分钟或满 8 个回合后，下一条消息开始新的一段。
- **页面**：只加载最近 600 条，可以向前翻页。自动来料和沉默的回合折叠显示；每条助手消息下有「在新对话中继续」，会把那段话作为引用带进一个新对话。

### 助手的电脑

全库只有一台属于助手的普通 orb，主线与所有助手对话共用。第一次用到时创建，空闲时照常冻结，调用前自动唤醒。

助手进程仍留在协调宿主沙箱里，经 `computer_bash`、`computer_read` / `computer_write` / `computer_edit`、`computer_grep` / `computer_glob` / `computer_find`、`computer_ast_grep` / `computer_ast_edit`、`computer_eval`、`computer_lsp`、`computer_wait` 遥控 orb 里一个不调模型的 omp 工具执行器（Oryn Core 的 `oryn_tool_*` RPC）。输出流式回传，图片原样到达，取消会传到 orb 里；`computer_upload` / `computer_download` 在电脑与文件库之间搬文件，`computer_record`（`{action: "start" | "stop"}`）录制电脑桌面并在停止后存入文件库（上限同 `computer_download`，超过则留在电脑的 `$HOME/recordings/` 下，控制联动与限制见[远程桌面与人机控制](#远程桌面与人机控制)）。这些工具的卡片与对应的普通工具相同。

`/assistant/computer` 页面的页头一行装下状态、页签与电源钮（就绪时暂停、冻结或停机时唤醒），更多菜单里可以复制 orb ID 或重置（删除后下次用到时重建）。三个页签铺满页头以下的空间，上次停留的页签会记住：「概览」显示规格、CPU / 内存曲线、最近 24 小时的状态时间线、工具是否就绪、助手与你最近使用的时间、镜像与版本；「桌面」通过共用任务栏查看、操作或接管远程桌面；「文件」浏览电脑里的文件。provider 与类型在「设置 → 全局助手」里选。

### 定时任务

| 模式 | 命令 | 行为 |
|---|---|---|
| 线程内定时 | `oryn schedule set` | 在单个已有线程内按 Cron 或固定间隔触发巡检提示词 |
| 项目级定时 | `oryn schedule add` | 每次拉起全新隔离线程，按 `keepLast` 自动归档历史运行；可指定开场的 role（`--role`）或模型 |

**运行前闸门**：两种模式都可以挂一个闸门（`--gate-command` / `--gate-host` / `--gate-timeout`，或编辑定时的「运行前闸门」）。每次运行（含手动触发）前，控制面先执行这条命令，不启动 agent、不调用模型。命令以退出码 0 结束且最后一个非空输出行是 `{"wakeAgent": false}` 时，本次运行记为跳过（`gate`）；其余情况（其它输出、非 0 退出、超时、执行环境不可用）照常运行，闸门的输出或失败原因附在提示词前面交给 agent。闸门只能由主人设置，agent 改写定时时沿用现值。

执行位置有两种：

- **控制面本机（默认，省略 `--gate-host`）**：在 orynd 所在机器的沙箱里用 `/bin/sh -c` 执行。工作目录是数据目录下 `gates/` 的一次性副本，脚本放在那里即可用 `./check.sh` 调用，沙箱里的写入不会写回；`HOME` / `TMPDIR` 也是一次性目录。沙箱以 nobody 身份运行（orynd 为 root 时），并施加 Landlock + seccomp：只能读系统目录，读不到控制面的数据、配置与密钥；TCP 只能连控制面开在回环上的出站代理，代理只放行公网地址，所以 `curl`、`python3` 能访问公网 HTTP(S)，但连不上内网和本机服务。命令跑在独立的 PID 命名空间里：命令结束或超时时，它留在后台的进程（含 `setsid` 脱离的）一并被杀掉。需要 Linux ≥ 6.7（Landlock ABI ≥ 4），且 orynd 能建 PID 命名空间（root，或非 root 时内核允许非特权 user namespace；默认 seccomp 配置的 Docker 容器里建不了）；不满足时不能保存本机闸门，改用 SSH 主机。
- **SSH 主机（`--gate-host <名称>`）**：经 SSH 网关在登记的主机上执行，适合要读那台机器状态的检查。主机按定时的范围解析：全局主机加所在项目的主机；项目定时是全自动运行，主机须允许全自动线程使用。执行记入 SSH 审计。`oryn schedule update --gate-host ""` 可改回本机执行。

**安静结束**：工作线程里全由自动化投递（定时、触发规则）开启的回合，如果 agent 的最后一条回复是 `[SILENT]`（整条，或独占第一行 / 最后一行，不区分大小写），这一回合按沉默结束：不置未读、不发完成通知，也不交给助手。主人亲自发过消息的回合、出错的回合不受影响；主线仍用 `stay_silent`。

### 成本与产出统计

控制面直接从会话条目入库模型调用、工具执行与生命周期事件（自动剔除分支 fork 造成的历史重复计费），按模型、项目、Space 或用途穿透统计成本、缓存命中率、TTFT 与交付提交数，支持 CSV 导出与日 / 月预算阈值系统通知。

## 记忆、GitHub 与 SSH

### Hindsight 记忆

orb 与 Runner 里的 agent 共用一个自托管的 [Hindsight](https://github.com/vectorize-io/hindsight) 记忆库，回合结束自动写入，下一轮自动召回。

- **隔离**：控制面网关替 agent 填写项目标签，同一项目的各个线程共享记忆，不同项目互不可见。
- **全局层**：写进全局层的内容（个人偏好、跨项目经验）先进候选队列，主人批准后才对所有项目生效。
- **模型中转**：Hindsight 自己调用的模型、嵌入与重排全部经控制面中转，可在同一协议内随时换模型。Gemini Decisions 重排使用随项目构建的 `gemini-rerank` 适配器。
- **管理**：「更多 → Agent → 记忆」可以浏览、搜索、按线程遗忘、审核候选、刷新 mental model、查看用量和导出；删除项目时，它的记忆一并删除。

部署见 [`deploy.md` 第 14 节](deploy.md#14-hindsight-记忆服务m16)。

### GitHub

部署见 [`deploy.md` 第 13 节](deploy.md#13-github-集成m15)。

- **OAuth App 授权**：在设置页填入自己注册的 GitHub OAuth App，连接「我的账号」与「Agent 账号」。触发规则、项目级定时与发布哨兵建的全自动线程默认用 Agent 账号。
- **orb 内免登录**：账号连接后，任何工作 orb 里的 git 与 `gh` 都可以直接使用（runner 与协调宿主除外）。真实令牌由出站代理注入，不进 orb。
- **PR 与回流**：项目按仓库地址自动绑定。线程推送的提交成为 PR 的头提交后，线程页头显示 PR 状态与 CI 结果，合并即标记已交付。评审、评论与 CI 失败会回流进线程，agent 自己的写操作不会回流。
- **事件来源**：有 admin 权限的仓库走仓库 webhook，并轮询投递日志补漏；其余仓库走 REST 轮询。
- **robomp 预设**：「分诊」「PR 评审」「发布哨兵」三个触发规则预设。分诊会登记 issue 状态，并支持实现授权、任务时限、完成提醒与问题自动关闭；PR 评审只发 COMMENT。
- **门禁**：项目可开启推送 / 开 PR 门禁，由出站代理强制执行：开启后推送或开 PR 前须先用 `github_prepare` 跑过检查。
- **发布哨兵**：发布提交的 CI 被阻塞时开线程修复，至多 5 轮，直到版本变为 green 或 failed。
- **审计**：agent 的每个 GitHub 写操作都记审计，保留 30 天。

### SSH 主机

在「更多 → Agent → SSH 主机」登记目标机（全局，或只对某个项目可见）与钥匙，orb 里的 agent 直接用主机名访问：`ssh://<名>/<路径>` 读写文件、终端工具里 `ssh <名>`、`ssh_exec_many` 一次在多台机器上并发执行。

- 连接都由控制面网关代拨（支持跳板链、首次连接固定指纹），私钥不进 orb，每条命令记审计。
- 全自动线程只能用明确放行的主机。
- 设置页可以测试连接、查看负载 / CPU / 内存 / 磁盘快照，直接打开网页终端或浏览远端文件。

## Boxes

box 是一台常驻机器：由 Provider（Docker / Sysbox / Firecracker）拉起，规格取 Provider 的 orb 类型。它不空闲冻结、不随线程回收，掉线后自动拉起。线程的 orb 负责构建，box 只负责运行：在线程里跑 `oryn boxes deploy`，把仓库的 `HEAD` 提交构建成一个 release 送上 box。一台 box 可以跑多个应用（app），每个 app 有自己的地址、密钥与数据目录。

- **创建**：「更多 › Boxes」里新建（或交给 Agent 去建），也可以让线程里的 agent 部署时加 `--create` 顺手建，或者让全局助手建。至多 16 台，每台至多 16 个 app。
- **部署**：仓库里放一份 `.oryn/box.yaml`（也认 `.amp/box.yaml`），最小写法：

  ```yaml
  services:
    web:
      command: bun run start   # 必须监听 $PORT
  build: bun install && bun run build
  ```

  字段：`services`（1–4 个服务，各有 `command`，可选 `cwd`）、`build`（部署前在 orb 里跑）、`source`（缺省 `true`：release 带源码与 `.git`；`false` 时只打包 `artifacts` 列出的构建产物）、`artifacts`、`include`（单仓多 app 时把仓库里别的目录一起带上）。第一次部署写 `oryn boxes deploy --on <box> --name <app>`，之后在同一个目录里 `oryn boxes deploy` 即可（target 记在 `.oryn/box-deploy.json`）。未提交的改动不会带上，先提交。
- **激活与回滚**：box 换到新 release、重启服务、等端口监听；起不来就退回上一个 release，不留半成品。保留当前 release 加前两个，可以在 box 页或用 `oryn boxes rollback` 回滚。
- **地址与公开性**：每个 app 的地址是 `https://<app>.<portal_domain>/`，与 thread portal、artifact 帧共用同一个泛域名与证书。app 默认公开，`--private` 或 box 页「设为私有」后要求主人登录；app 收到的请求带 `X-Oryn-Authenticated: owner=yes|no`。没有配置 `portal_domain` 时 app 没有地址。
- **环境与数据**：进程拿到 `PORT`、`ORYN_DEPLOYMENT_URL`、`ORYN_DEPLOYMENT_NAME`、`ORYN_DEPLOYMENT_BOX` 与 `ORYN_DEPLOYMENT_DATA_DIRECTORY`；数据只写进数据目录（`~/apps/<app>/data`），它在部署与重启之间保留。密钥用 `oryn boxes secrets set` 或 box 页的「密钥…」设置，改动在重启或下次部署后生效；`--plain` 的是明文环境变量，可以读回。
- **运行时段**：box 可以设每日的开机、关机时刻与时区；手动启停只保持到下一个时间点。停着的 box 上的线程不接收消息，要先在 Boxes 页启动。
- **在 box 上开线程**：box 页的「新线程」或首屏执行位置里的 Boxes 分组，可以把线程开在机器（`~`）或某个 app 的线上目录（`~/apps/<app>/current`）上，线程直接操作线上的应用和数据。带源码的 release 在 box 上改了代码、没有推送时，新的部署会拒绝覆盖（`box_changes`），要么在 box 上的线程里提交并推送，要么加 `--discard-box-changes`。
- **悬停预览**：app 根页面的 `<head>` 里声明 `<meta name="oryn-preview" content="v1; enabled; iframe">`，box 页悬停 app 徽标时显示实时预览（带 `?oryn-preview=light|dark` 参数，app 可以据此调整样式）。
- **边界**：部署只能在线程的 orb 里进行；同一台 box 上的 app 与线程以同一个用户运行，彼此没有隔离，不可信的 app 放到单独的 box；box 的数据就是那台机器的磁盘，删 box 即丢；全自动线程不能使用 box；orb 里的 agent 不能删 box，删除只能由主人在 Boxes 页、设备令牌 CLI 或经全局助手的确认卡完成。

## Artifacts

orb 线程、Runner 线程与全局助手的 Agent 都能用 `create_artifact` / `update_artifact` 等工具做出页面、画布、文档（Markdown）与幻灯片。

- **版本**：每次写入生成一个新版本，冲突按文件粒度检查；可以恢复旧版本，删除的进「最近删除」保留 30 天。
- **隔离渲染**：每个 artifact 在不透明源的沙箱帧里显示（配置了 `portal_domain` 时用 `a-<令牌>` 泛域名，否则用主域的 `/_af/` 路径），只能加载自身文件与白名单 CDN。控制面主机上带沙箱的 headless Chromium 负责渲染缩略图、PNG 与 PDF。
- **入口**：「更多」分区的 `/artifacts` 总览页（大卡片预览、类型标签、搜索、筛选、导入、回收站）；线程右面板的 Artifacts 标签；转录里的 artifact 卡片；命令面板。
- **查看器** `/artifacts/<id>`：版本历史、评论（可发给线程）、元素直接编辑、导出（HTML / zip、Word、Markdown、PowerPoint、PDF）和分享。
- **画布编辑器**：工具条、图层与属性面板；画框可声明调节参数，在「调节」面板里即时预览并写回；选中的画框与标注可连同合成图「交给 Agent」。
- **演示与聚焦**：页面与画布可铺满窗口逐页演示，单个画框可全尺寸聚焦查看；手机上画布只读，演示可左右轻扫翻页。
- **在场**：查看器与卡片显示正在读、正在改的线程头像；画布上显示 agent 指针，可以「跟随」它的镜头。
- **页面能力**：页面可通过 `oryn.use("db" | "files" | "sample")` 存数据、只读项目文件、向用户的模型提问；后两项首次使用需要用户同意，可在 设置 › Artifacts 收回。
- **发布**：可以发布成私有、访问码或公开的链接；发布访问码与公开链接前会做密钥扫描。

## 客户端

### 原生壳

Windows / macOS / Linux 桌面端与 Android、iOS 客户端共用一套 Tauri 2 工程（`web/src-tauri`）。客户端本身只携带极简的配对连接页，配对后加载所连服务器自身的 Web UI，服务端升级即全端同步。设备令牌只驻留在 Rust 进程与系统凭据库（macOS 钥匙串、Windows 凭据管理器、Linux Secret Service、Android Keystore），网页脚本无法读取。

### 桌面

- 无系统标题栏的同源设计：macOS 保留原生红绿灯，与侧栏品牌行同一行，启动时实测校准位置；macOS 26 起挂 unified 工具栏，卡片按窗口外框做同心圆角。Windows / Linux 自绘窗口按钮，Linux 遵循 GTK 标题栏布局。
- 系统托盘、全局唤醒快捷键与 `oryn://` 深链接。

细节见 [`desktop.md`](desktop.md)。

### 移动

- `<600dp` 窄屏：屏幕圆角同心的下沉式侧栏、悬浮毛玻璃底栏、右上角快捷视图菜单、系统分享接收。
- 推送：RFC 8291 端到端加密，orynd 只有两条路径。**UnifiedPush**（`foss` 包，零 Google 依赖）复用 Web Push；**官方推送网关**（`https://push.oryn.best`）让官方 iOS 包与 `gms` 包连任意自部署 orynd 也能收推送：配对后自动启用，网关只见密文、转给 APNs / FCM，APNs key 与 Firebase 服务账号只在网关上，免注册、由手机在网关上授权与吊销。工具审批、确认这类可一触作答的提问直接在通知上带「允许 / 拒绝」等按钮（Android 需解锁后点按，浏览器 Web Push 同样支持），后台作答不拉起界面；请求在别处作答后旧按钮自动撤回。
- iOS 26：原生 Liquid Glass 线程页头与系统 `UITabBar` 底栏，随下沉侧栏的卡片开合；App 图标可在「设置 → 外观」换成品牌色版本。iOS 经 TestFlight 分发；APNs 推送由 Notification Service Extension 在锁屏前解密，真机验收待 TestFlight。

细节见 [`mobile.md`](mobile.md)。

### 终端

- `oryn thread attach <线程>`：在终端内流式查看转录，支持实时输入引导（steer）、作答与计划审批。
- `oryn sync <线程>`：把远端 orb 内的提交与未提交改动实时镜像到本机干净检出（`Ctrl-C` 自动还原，`--apply` 一次性落盘）。

### 本机浏览器中继（Chrome 扩展）

需要复用日常 Chrome 的已登录态、访问本机 `localhost` / 公司内网或使用住宅 IP 时，可在 Chrome 中加载 `oryn-core/packages/browser-relay` 扩展并切换到「Oryn 云端模式」：

- **免额外本地进程**：扩展通过配对码完成认证后直连 `orynd`，在线程页头或扩展弹窗中一键绑定到指定工作线程，不依赖桌面 App 或常驻 CLI；在「设置 → 设备」可随时吊销。
- **与云端桌面并存**：工作线程的 `browser.open(...)` 默认仍走 orb 内的云端桌面 Chromium；需要操作本机 Chrome 时由 agent 显式使用 `app: "relay"`。
- **本机隐私与非阻塞审批**：未被主动点选共享的现有标签页对云端完全不可见；新建标签页（不限站点）以及跨主域名跳转、读取 Cookies 等高危 CDP 默认进入扩展弹窗待审批队列（支持「允许这次」「本会话总是允许」「拒绝」），批准后自动通知线程重试，不会因等待审批触发超时关页。

## 安全边界

完整威胁模型与加固清单见 [`deploy.md` 第 7 节](deploy.md#7-安全)。

### 出站代理凭据隔离

默认 `proxy` 模式下，导入的 `models.yml` 明文 API Key 与 `git/*` 令牌存入控制面主密钥加密库，下发到 orb 的配置只含 `oryn-ph-…` 占位符。请求经 `orbd` 本地端口 `127.0.0.1:7811` 回到 `orynd`，按绑定的上游主机注入真实值，并把响应中回显的凭据脱敏回占位符。只有显式设为 `env` 模式的自定义密钥，或未绑定上游 `hosts` 的模型 Key，才会降级为环境变量下发。[项目级](#项目级密钥与环境变量)的 Git 令牌同样只由出站代理注入、不进 orb；项目级环境变量只以环境变量下发给本项目的 orb。

### Git 访问范围

- **github.com**：用 OAuth 账号令牌注入，能读写哪些仓库取决于账号自身权限，不按项目仓库限制。项目开启推送 / 开 PR 门禁时，出站代理要求先用 `github_prepare` 跑过检查；只读评审线程在推送协商阶段即被拒绝。
- **其它 Git 主机（PAT）**：令牌先取 orb 所属项目的 `git/<主机>/token`，没有再取全局的。绑定了 `https://` 仓库地址的项目 orb 只允许对该仓库执行读写（`git-upload-pack` / `git-receive-pack`），同主机其它仓库一律 `403`；未绑定项目的 orb 只放行只读克隆，拒绝一切推送。
- **Oryn 托管仓库**：托管项目的 orb 只能读写本项目的托管仓库（同一 Oryn 地址上的别的托管仓库 `403`），请求在控制面本地服务、不带任何令牌；只读评审线程不能推送；推上来的对象先过 `git fsck`。主人本机经 `/git/` 访问，只认设备令牌。
- **Git LFS**：与 git 用同一套规则，经出站代理注入同一个令牌。上传对象、建锁、解锁与推送前的锁校验算写操作：没有项目的 orb 不能上传，只读评审线程也不能；下载算读。令牌不进 orb：LFS 批量接口的请求与响应都由代理解析后重写，上游在响应里回显或新签发的凭据会被去掉；存放对象的其它主机（对象存储的签名地址）由 orb 直连。被拒时 `git lfs` 输出的原因以 `oryn: ` 开头。

### 令牌轮换与单向信任

- **orb 令牌**：`oot_…` 由 `HMAC(key, orbID : 代数)` 派生，每次创建、唤醒及拍摄快照后立即轮换，快照磁盘内不留有效令牌（Firecracker guest 令牌只驻留内存 `tmpfs`）。
- **Runner 单向边界**：控制面永不向 Runner 下发模型配置或环境变量密钥，只开一条仅通往记忆网关 `/memory/` 的专用通道（其它出站路径一律 403，Hindsight 的 key 不进 Runner）。
- **谁能操控 Runner**：只有主人与全局助手。全局助手可以像主人一样在 Runner 上新建线程、发消息、读取、归档、读写线程目录里的文件，删除要主人点确认卡；Space 协调者与 orb 内 Agent 禁止读写或操控任何 Runner 线程，普通 orb 里产出的内容不能经它们变成你机器上的指令。
- **协调沙箱**：全局助手所在的沙箱只有一个出口，即回环上的出站代理端口；联网与 MCP 都经 `orynd` 的正向代理（只连公网地址，MCP 鉴权头由 `orynd` 注入）。网页、搜索结果与 MCP 的返回都作为不可信数据交给助手。
